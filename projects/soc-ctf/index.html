CYBERSECURITY / CASE STUDY

SOC Analyst CTF

A four-stage investigation lab connecting SIEM alerts, Windows processes, persistence, network events, and identity evidence.

From one alert to an incident report

This project packages a guided Security Operations Center investigation for approximately 40 participants and a 60-minute session. Students begin with a PowerShell alert and correlate several evidence sources to establish scope and recommend a response.

This is a public project case study. The full Elastic lab runs in a separately configured training environment.

The investigation

  1. Alert triage: Evaluate the detection and identify the affected host.
  2. Host investigation: Reconstruct the process tree and distinguish suspicious execution from legitimate administration.
  3. Persistence hunting: Correlate staged files and scheduled tasks.
  4. Scope and response: Connect DHCP, network, and Entra ID events; document findings and containment recommendations.

How the lab is assembled

Separate benign and attack-training inputs feed repeatable builders and validators. Elasticsearch templates and Kibana assets make the evidence searchable. Ingestion applies one fixed time offset across the sources, preserving the relationships in the investigation timeline.

Windows + DHCP + Network + Entra ID
                  ↓
       Build and validate datasets
                  ↓
        Elasticsearch → Kibana
                  ↓
      Investigation and incident report

The deliverables include validation scripts, ingestion tools, dashboards, student guidance, and instructor materials. The public page intentionally contains no instructor answer key or connection credentials.

Skills demonstrated

Detection triage, timeline correlation, data engineering, false-positive analysis, repeatable lab delivery, and incident-response communication.

The training artifacts use reserved example destinations and inert payloads. This case study does not host vulnerable services or execute attack code.
